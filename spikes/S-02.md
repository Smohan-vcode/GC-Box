# S-02  Detecting completion of a Google eSignature request

## Inputs
- A test Doc with signature fields
- Two test signer addresses

## Outputs
- spikes/findings/S-02.md

## Steps
1. Stop: ask the owner to send one eSignature request from the test Doc and have both signers complete it.
2. Record where the completed PDF and audit trail are created, their owner, names and MIME types.
3. Record every notification mail received by the requester: sender, subject pattern, body markers, attachments.
4. Check whether the Drive API exposes any signature state on the file or the completed PDF.
5. Repeat with a declined request and a cancelled request.
6. Propose a detection rule: file pattern, mail pattern, or both; state its failure modes.
7. Write the finding.

## Human steps
- Send, sign, decline and cancel the test requests (Google eSignature cannot be driven by code).

## Exit criteria
- Finding names a rule that identified completion in two completed runs and did not fire on the declined or cancelled runs.
- If no reliable rule exists, the finding says so and proposes manual confirmation in the cockpit.

## Evidence
- setup-status.json entry with commit reference
