# T6-03  Template review and activation

## Inputs
- Bindings, Dictionary, TemplateFields

## Outputs
- Templates review screen
- engine/cockpit/review.js

## Steps
1. Show the document with each bracket highlighted beside its suggested kind and key.
2. Reviewer confirms or changes kind; for constant and note picks or creates a dictionary key; for deal picks or creates a field (label, type, required, counterparty column); for choice groups alternatives into one choice field with options.
3. Apply-to-all: confirm the same decision for identical text with matching context within the template.
4. Fields marked never_store in the catalogue are fixed as never_store and cannot be mapped to a stored field.
5. Reviewer confirms class, signers, approval scope, execution action, retention class, review period.
6. Activate is enabled only when every binding is confirmed; activation supersedes the earlier version.
7. Create the master copy with brackets intact; record master_file_id.

## Human steps
- None.

## Exit criteria
- A template with one unconfirmed binding cannot be activated.
- After review of PS-MNDA: company address brackets bound to dictionary keys, counterparty brackets bound to fields with counterparty columns.
- Activating version 2 sets version 1 to SUPERSEDED.

## Evidence
- setup-status.json entry with commit reference
