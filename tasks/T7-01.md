# T7-01  Send form, numbering and drafts

## Inputs
- Templates, TemplateFields, Counterparties

## Outputs
- Send screen
- engine/cockpit/documents.js
- engine/cockpit/numbering.js

## Steps
1. Picker lists ACTIVE signed templates the user may send; company domain only with company.send.
2. Form: counterparty (pick or create), signer, then the template's fields in order; counterparty columns prefilled.
3. Numbering: next sequence per reference pattern, year tokens resolved, issued under lock; never reused.
4. Save creates a Documents row in DRAFT, DocumentTerms rows (never_store fields excluded), a rendered draft in the counterparty's folder.
5. Preview shows the rendered draft before any further step.

## Human steps
- None.

## Exit criteria
- Two simultaneous sends receive different numbers.
- A draft for PS-MNDA has reference PS-NDA-0001 on the test tenant.
- A never_store value entered in the form is not found anywhere in the register.

## Evidence
- setup-status.json entry with commit reference
