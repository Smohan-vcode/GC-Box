# T0-01  Repository scaffold and configuration validation

## Inputs
- docs/SPEC.md
- schema/company.schema.json

## Outputs
- engine/cli/ package `box`
- commands: validate, check-literals
- pyproject.toml, tests/

## Steps
1. Create the Python package in engine/cli with Typer; entry point `box`.
2. Implement `box validate`: load company.yaml and every file under `files`, validate against schema/company.schema.json, report all errors.
3. Implement `box validate --for <task-id>`: also fail on empty values the task lists under Inputs.
4. Implement `box check-literals`: collect strings from company.yaml > company and directory/users.yaml names; fail if any appears under engine/, defaults/, tasks/, spikes/, assistants/ or docs/, except inside a line marked `example:`.
5. Add pytest tests for both commands, including a failing fixture for each.
6. Add a README with the bootstrap order.

## Human steps
- None.

## Exit criteria
- `box validate` passes on the repository's company.yaml.
- `box validate` on a copy with primary_domain removed fails and names the key.
- `box check-literals` fails when the trading name is added to a file under engine/.
- pytest passes.
