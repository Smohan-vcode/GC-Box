# T4-05  Inbound endpoint

## Inputs
- company.yaml > integrations
- SPEC section 10

## Outputs
- engine/cockpit/inbound/ (doPost, schemas)

## Steps
1. doPost accepts JSON with `type`, `secret`, `payload`; compare secret in constant time with the script property.
2. Validate payload against the JSON schema for its type; reject unknown types.
3. lead.create inserts a Leads row; order.announce and document.request create a DRAFT Documents row with source inbound.
4. Idempotency: an `id` seen before returns the earlier result.
5. Log every call, accepted or refused, without the secret.

## Human steps
- None.

## Exit criteria
- Wrong secret returns 403 and writes no row.
- The same lead id posted twice creates one row.
- Invalid payload returns 400 with the failing field.

## Evidence
- setup-status.json entry with commit reference
