# T5-02  Approval rules

## Inputs
- defaults/roles.yaml > default_rules
- SPEC section 9

## Outputs
- Approval rules screen
- engine/cockpit/approvals.js
- Node tests

## Steps
1. Seed ApprovalRules from defaults on first run.
2. `rulesFor(document)`: most specific match wins: template code over domain; then condition.
3. `open(document)`: create Approvals rows for each step; notify holders of the role.
4. `decide(approval, decision, comment)`: enforce the self-approval safeguard; on last approval transition the document to READY; on return, to DRAFT.
5. Fallback: a daily job reassigns pending approvals older than fallback_days to the fallback role.
6. Screen for owners to add, edit and deactivate rules.

## Human steps
- None.

## Exit criteria
- Tests: specificity order; value_above threshold; two-step approval; self-approval refused when another holder exists and recorded when none does; fallback reassignment.
