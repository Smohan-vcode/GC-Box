# T7-04  Completion detection, filing and execution actions

## Inputs
- spikes/findings/S-02.md

## Outputs
- engine/cockpit/signature/completion.js
- engine/cockpit/actions/

## Steps
1. Implement the detection rule from S-02 as status(document); run it every 15 minutes for SENT documents.
2. If S-02 found no reliable rule, provide `Mark executed` with upload of the completed PDF, and skip automatic detection.
3. On completion: move the PDF and audit trail to the executed folder for the counterparty as `<date>_<counterparty>_<code>_EXECUTED`, lock them, set executed_at, effective_on and expires_on from term.
4. Run the template's execution action from actions/: clear_counterparty, open_customer, open_partner, open_vendor, open_joiner_checklist, link_to_lead_document, call_order_system, filing_reminder, none.
5. Each action is idempotent and writes an Events row.
6. Declined or cancelled requests move the document to DECLINED or VOIDED.

## Human steps
- None.

## Exit criteria
- A completed test request is filed, locked and EXECUTED within 30 minutes with no manual step, or the manual path is used as S-02 directs.
- clear_counterparty sets the counterparty's NDA document and expiry.
- Running the job twice files nothing twice.
