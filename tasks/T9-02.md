# T9-02  Order system connection

## Inputs
- company.yaml > integrations.order_system

## Outputs
- engine/cockpit/actions/call_order_system.js
- inbound type order.announce

## Steps
1. order.announce payload: external_sale_id, customer legal name and contact, plan, price, currency. Create or match the counterparty, create the order-form DRAFT and an Orders row.
2. call_order_system on execution: POST the order to base_url with the token from script properties; store returned licence and invoice identifiers; retry three times with backoff; on failure alert and leave a retry action.
3. Contract tests against a mock server in the repository; the real message format is confirmed with the owner before live use.

## Human steps
- Provide the order system's base URL, token and confirm the message format.

## Exit criteria
- A posted sale creates one order-form draft.
- Execution calls the mock once and stores its identifiers; a second run does not call again.

## Evidence
- setup-status.json entry with commit reference
