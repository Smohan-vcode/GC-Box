# T6-01  Template intake scan

## Inputs
- company.yaml > legal
- content/legal-pack/catalogue.yaml
- spikes/findings/S-01.md

## Outputs
- engine/cockpit/intake.js
- Templates screen: Scan now

## Steps
1. List files in each domain subfolder of the intake folder; skip file ids already in Templates.source_file_id.
2. Parse code and title with legal.file_name_pattern; a file that does not match is logged and left in place.
3. Convert Word to Google Docs with the method from S-01.
4. Read the header block: find the label row and value row; take reference pattern, framework and version using legal.header_label_patterns. Missing values are left empty and flagged.
5. Take domain, class, signers, action, retention and language from the catalogue by code; without a catalogue entry use the subfolder for domain and leave the rest for review.
6. If a template with the same code exists, set `supersedes` and continue as a new version.
7. Insert the Templates row as NEEDS_REVIEW; move the file to the domain's template folder as `<code>_<version>`; one notification per scan.
8. Trigger every 15 minutes and a Scan now action.

## Human steps
- None.

## Exit criteria
- The pack's 31 Word files produce 31 Templates rows and an empty inbox.
- A second scan creates nothing.
- PS-MNDA has reference pattern, framework and version filled.
- A non-matching file name is reported, not processed.

## Evidence
- setup-status.json entry with commit reference
