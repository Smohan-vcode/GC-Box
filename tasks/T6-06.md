# T6-06  Refresh of notices and records; pack export

## Inputs
- Notices tab

## Outputs
- engine/cockpit/refresh.js
- Notices and records screen (queue part)

## Steps
1. When a dictionary value changes, re-render each published or record template that uses it as a new Notices row in PENDING_APPROVAL with reason data change.
2. Approval by an owner moves it to PENDING_PUBLICATION for published documents, or CURRENT for records; the earlier version becomes SUPERSEDED.
3. Publication is a manual step: the owner records the URL and date.
4. Pack export: render every ACTIVE template with current data, deal fields left as brackets, to Word and PDF in a dated folder under 08 Pack exports.

## Human steps
- None.

## Exit criteria
- Changing one constant used by three notices creates three pending rows.
- Export contains one Word and one PDF per ACTIVE template.

## Evidence
- setup-status.json entry with commit reference
